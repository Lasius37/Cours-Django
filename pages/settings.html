    Rôle du fichier settings.py

    Le fichier settings.py contient les paramètres globaux du projet. On y configure notamment :

    • les applications installées ;
    • les templates HTML ;
    • les fichiers statiques ;
    • la base de données ;
    • la sécurité et le mode debug.

    Après la création d'une application avec startapp, il faut l'ajouter dans INSTALLED_APPS.

    Régler les paramètres généraux

    On commence par modifier quelques paramètres dans settings.py : 

    LANGUAGE_CODE = "fr-FR"

TIME_ZONE = "Europe/Paris"

    Ces paramètres permettent d'adapter le projet à la langue et au fuseau horaire utilisés.

    Déclarer une application

    Django doit connaître les applications du projet pour pouvoir les utiliser. On les ajoute à la liste INSTALLED_APPS, déjà déclarée dans settings.py . 

    INSTALLED_APPS = [
    "django.contrib.admin",
    "django.contrib.auth",
    "django.contrib.contenttypes",
    "django.contrib.sessions",
    "django.contrib.messages",
    "django.contrib.staticfiles",

    "apps.mon_app",                 #  Ajouter le nom de chaque application du projet
]

    Une fois l'application ajoutée, Django peut utiliser ses modèles, ses templates, ses fichiers d'administration, ses migrations.

    Configurer les templates

    Django peut charger des templates depuis les applications, mais on peut aussi définir un dossier global. Le dossier templates a déjà été créé à la racine du projet, on y ajoute le fichier base.html. 

    mon_projet/
│
├── templates/
│   └── base.html

    Il faut ensuite déclarer ce dossier dans settings.py : 

    TEMPLATES = [
    {...
        'DIRS': [BASE_DIR / "templates"],
        'APP_DIRS' = True,
    ...}
]

    Django cherchera alors les templates :

    • dans le dossier global templates
    • dans les dossiers templates des applications

    Configurer les fichiers statiques

    Les fichiers statiques correspondent aux fichiers front-end : CSS, JavaScript, images, polices.

    Le dossier static est déjà à la racine du projet. On peut y ajouter de nombreus sous-dossiers selon les besoins, si ces fichiers sont nombreux : 

    mon_projet/
│
├── static/
│   ├── audios/         les fichiers audio du projet
│   ├── css/            les feuilles de style
│   ├── documents/      les documents (pdf...) du projet
│   ├── fonts/          les polices d'écriture
│   ├── images/         les images fournies par le développeur
│   ├── js/             les scripts
│   └── videos/         les fichiers vidéo du projet

    On indique ensuite où se trouve ce dossier dans settings.py : 

    STATICFILES_DIRS = [
    BASE_DIR / "static"
]

    L'URL utilisée pour accéder aux fichiers statiques est définie par : 

    STATIC_URL = "/static/"
STATIC_ROOT = BASE_DIR / "staticfiles"  # Cette ligne sera utilisée au moment du déploiement

    Configurer les fichiers médias

    Les fichiers médias correspondent aux fichiers envoyés par les utilisateurs, par exemple des images ou des documents. Le dossier media existe déjà : 

    mon_projet/
│
└── media/

    On ajoute ensuite les paramètres suivants dans settings.py : 

    MEDIA_URL = "/media/"
MEDIA_ROOT = BASE_DIR / "media"  # Cette ligne sera utilisée au moment du déploiement

    Ces paramètres seront utilisés plus tard pour servir les fichiers médias. Selon les besoins, on peut ajouter des sous-dossiers pour séparer les fichiers.

    Erreurs fréquentes

    • Oublier d'ajouter l'application dans INSTALLED_APPS : Django ignore l'application.
    • Oublier de créer les dossiers templates ou static : les fichiers ne sont pas trouvés.
    • Modifier la configuration sans redémarrer le serveur : les changements ne sont pas pris en compte.
    • Utiliser un chemin incorrect dans STATICFILES_DIRS : les fichiers statiques ne sont pas chargés.
