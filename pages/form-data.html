Traiter les données d’un formulaire

Une fois le formulaire affiché dans le template, l’étape suivante consiste à récupérer et traiter les données envoyées par l’utilisateur.

En Django, ce traitement se fait généralement dans la vue. La vue doit :

  • détecter si le formulaire a été envoyé
  • récupérer les données
  • vérifier si elles sont valides
  • utiliser ces données ou réafficher le formulaire avec les erreurs

Vérifier la méthode de requête

Quand un utilisateur affiche la page pour la première fois, la requête est souvent de type GET. Quand il envoie le formulaire, la requête est généralement de type POST. 

def contact(request):
    if request.method == "POST":
        pass
    else:
        pass

Cette structure permet à la vue de distinguer :

  • l’affichage initial du formulaire
  • le traitement des données envoyées

Récupérer les données avec request.POST

Quand le formulaire est envoyé avec method="post", les données saisies sont accessibles dans request.POST. 

from django.shortcuts import render
from .forms import ContactForm


def contact(request):
    if request.method == "POST":
        form = ContactForm(request.POST)
    else:
        form = ContactForm()

    context = {"form": form}

    return render(request, "contact.html", context)

Ici, Django remplit le formulaire avec les données reçues. Cela permet ensuite de vérifier si les champs contiennent des valeurs correctes.

Vérifier le formulaire avec is_valid()

Une fois le formulaire rempli avec request.POST, on peut demander à Django de vérifier les données avec la méthode is_valid(). 

def contact(request):
    if request.method == "POST":
        form = ContactForm(request.POST)
        if form.is_valid():
            pass
    else:
        form = ContactForm()

    context = {"form": form}

    return render(request, "contact.html", context)

La méthode is_valid() retourne :

  • True si les données respectent les règles du formulaire
  • False si certaines données sont manquantes ou invalides

Si le formulaire n’est pas valide, Django peut réafficher automatiquement les champs avec les messages d’erreur associés.

Utiliser cleaned_data

Quand form.is_valid() renvoie True, les données validées sont disponibles dans form.cleaned_data. 

def contact(request):
    if request.method == "POST":
        form = ContactForm(request.POST)
        if form.is_valid():
            name = form.cleaned_data["name"]
            email = form.cleaned_data["email"]
            message = form.cleaned_data["message"]
    else:
        form = ContactForm()

    context = {"form": form}

    return render(request, "contact.html", context)

cleaned_data contient les valeurs déjà vérifiées et converties dans un format utilisable par Python. Il vaut mieux utiliser cleaned_data plutôt que lire directement les valeurs dans request.POST.

Réagir après l’envoi

Une fois les données récupérées et validées, la vue peut faire plusieurs choses :

  • afficher un message de confirmation
  • enregistrer un objet dans la base de données
  • envoyer un email
  • rediriger l’utilisateur vers une autre page
from django.shortcuts import redirect, render
from .forms import ContactForm


def contact(request):
    if request.method == "POST":
        form = ContactForm(request.POST)
        if form.is_valid():
            return redirect("home")
    else:
        form = ContactForm()

    context = {"form": form}

    return render(request, "contact.html", context)

Ici, si le formulaire est valide, l’utilisateur est redirigé vers la page "home".

Erreurs fréquentes

  • Tester request.method avec "post" au lieu de "POST" : la condition ne fonctionne pas.
  • Créer ContactForm() au lieu de ContactForm(request.POST) dans le bloc POST : les données envoyées ne sont pas récupérées.
  • Utiliser cleaned_data avant is_valid() : les données ne sont pas encore validées.
  • Lire directement les champs dans request.POST au lieu d’utiliser form.cleaned_data : on contourne le système de validation de Django.
  • Oublier de renvoyer le formulaire au template quand il n’est pas valide : la page ne peut pas réafficher les erreurs.
  • Oublier method="post" dans la balise <form> : les données ne sont pas envoyées comme prévu.
