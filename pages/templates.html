Rôle des templates

Un template est un fichier HTML utilisé par Django pour afficher une page dans le navigateur. Il permet de séparer :

  • la logique Python dans les vues
  • la structure HTML dans les templates

Cette séparation rend le code plus clair, plus modulaire et plus facile à maintenir : une vue prépare la réponse, puis Django charge le template demandé avec render().

Où placer les fichiers HTML

Les templates sont généralement placés dans un dossier templates à l'intérieur de l'application. 

apps/
└── mon_app/
    ├── views.py
    ├── urls.py
    └── templates/
        └── home.html

Cette organisation permet à Django de retrouver facilement les fichiers HTML appelés par les vues. Le nom du fichier indiqué dans render() doit correspondre exactement au nom réel du template.

Créer un premier template

Un template peut être un simple fichier HTML classique. 

<!DOCTYPE html>
<html lang="fr">
<head>
    <meta charset="UTF-8">
    <title>Accueil</title>
</head>
<body>
    <h1>Bienvenue sur mon site Django</h1>
    <p>Ceci est ma première page générée avec un template.</p>
</body>
</html>

Ce fichier peut être enregistré sous le nom home.html dans le dossier templates.

À ce stade, le template ne contient encore aucune syntaxe spécifique à Django.

Lier la vue au template

Une fois le fichier HTML créé, il faut demander à la vue de l'afficher. 

from django.shortcuts import render

def home(request):
    return render(request, "home.html")
  • render() renvoie une réponse HTML
  • request correspond à la requête reçue
  • "home.html" est le nom du template à charger

Si l'URL est correctement reliée à cette vue, la page HTML s'affichera dans le navigateur.

Créer un template de base

Quand plusieurs pages partagent la même structure, il devient utile de créer un template commun, souvent nommé base.html. Ce fichier peut contenir les éléments répétés sur toutes les pages :

  • le squelette HTML
  • l'en-tête
  • la navigation
  • le pied de page

Cela évite de recopier le même code HTML dans chaque template. 

<!DOCTYPE html>
<html lang="fr">
<head>
    <meta charset="UTF-8">
    <title>Mon site</title>
</head>
<body>
    <header>
        <h1>Mon site Django</h1>
    </header>

    {% block content %}{% endblock %}

    <footer>
        <p>Pied de page</p>
    </footer>
</body>
</html>

La zone définie par block content sera remplacée par le contenu propre à chaque page.

Hériter d’un template

Pour réutiliser le template de base, un autre template peut hériter de base.html avec extends. 

{% extends "base.html" %}

{% block content %}
    <h2>Accueil</h2>
    <p>Bienvenue sur la page d'accueil.</p>
{% endblock %}
  • {% extends "base.html" %} indique que ce template hérite du template de base
  • {% block content %} ouvre une zone de contenu
  • {% endblock %} ferme cette zone

La ligne {% extends "base.html" %} doit être la première du fichier (hors commentaires).

Django insère alors ce contenu dans le bloc correspondant du fichier base.html. Ce système permet de construire plusieurs pages différentes tout en gardant une structure commune.

Erreurs fréquentes

  • Créer le fichier HTML au mauvais endroit : Django ne trouve pas le template.
  • Se tromper dans le nom du template dans render() : TemplateDoesNotExist.
  • Oublier de mettre {% extends %} en première ligne: le template ne fonctionne pas correctement.
  • Oublier {% endblock %} : le template devient invalide.
  • Placer du contenu en dehors du bloc principal dans un template enfant : structure confuse ou résultat inattendu.
  • Confondre la logique Python des vues et l'affichage HTML : code peu lisible.
