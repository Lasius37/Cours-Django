    Validation automatique des champs

    Django valide automatiquement les données selon le type de chaque champ du formulaire. La validation est déclenchée quand on appelle form.is_valid(). 

    from django import forms


class ContactForm(forms.Form):
    name = forms.CharField(max_length=100)
    email = forms.EmailField()
    age = forms.IntegerField(min_value=10, max_value=99)

    Ici :

    • name ne peut pas dépasser 100 caractères ;
    • email doit contenir une adresse email valide ;
    • age doit être un entier compris entre 10 et 99.

    Si une donnée ne respecte pas ces contraintes, Django considère que le formulaire n’est pas valide.

    Afficher les erreurs dans le template

    Si form.is_valid() renvoie False, Django conserve les données saisies et ajoute les messages d’erreur au formulaire. 

    <form method="post">
    {% csrf_token %}
    {{ form.as_p }}
    <button type="submit">Envoyer</button>
</form>

    Avec {{ form.as_p }} ou {{ form }} , les erreurs sont affichées automatiquement à côté des champs concernés. On peut aussi afficher les erreurs plus explicitement : 

    {{ form.errors }}

    Cela permet de visualiser rapidement les problèmes détectés par Django.

    Valider un champ avec clean_<my_field>()

    Pour ajouter une règle personnalisée sur un champ précis, on peut écrire une méthode clean_<my_field>() dans la classe du formulaire. 

    from django import forms
from django.core.exceptions import ValidationError


class ContactForm(forms.Form):
    name = forms.CharField(max_length=100)

    def clean_name(self):
        name = self.cleaned_data["name"]

        if len(name) < 3:
            raise ValidationError("Le nom doit contenir au moins 3 caractères.")

        return name

    Ici, Django appelle automatiquement clean_name() pendant la validation.

    • si la valeur est correcte, la méthode retourne la valeur
    • sinon, elle lève une erreur de validation

    Cette méthode est utile pour ajouter une règle métier simple sur un seul champ.

    Valider plusieurs champs avec clean()

    Quand la validation dépend de plusieurs champs à la fois, on peut redéfinir la méthode clean(). 

    from django import forms
from django.core.exceptions import ValidationError


class RegistrationForm(forms.Form):
    password = forms.CharField(widget=forms.PasswordInput)
    confirm_password = forms.CharField(widget=forms.PasswordInput)

    def clean(self):
        cleaned_data = super().clean()
        password = cleaned_data.get("password")
        confirm_password = cleaned_data.get("confirm_password")

        if password != confirm_password:
            raise ValidationError("Les deux mots de passe doivent être identiques.")

        return cleaned_data

    Ici, la validation ne porte pas sur un champ isolé, mais sur la cohérence entre password et confirm_password. La méthode super().clean() permet de conserver le comportement normal de Django avant d’ajouter la règle personnalisée.

    Lever une ValidationError

    Pour signaler qu’une donnée n’est pas acceptable, Django utilise l’exception ValidationError. 

    from django.core.exceptions import ValidationError

raise ValidationError("Ce champ contient une valeur invalide.")

    Cette exception peut être utilisée :

    • dans une méthode clean_<my_field>() ;
    • dans la méthode clean() ;
    • dans certains validateurs personnalisés.

    Le message fourni sera affiché à l’utilisateur dans le formulaire.

    Erreurs fréquentes

    • Utiliser cleaned_data avant is_valid() : les données ne sont pas encore validées.
    • Oublier de retourner la valeur dans clean_<my_field>() : la donnée validée n’est pas correctement renvoyée.
    • Oublier super().clean() dans clean() : certaines données peuvent ne pas être récupérées correctement.
    • Lever une exception classique au lieu de ValidationError : Django n’affiche pas l’erreur comme une erreur de formulaire normale.
    • Écrire clean_name au lieu de clean_name() comme méthode de la classe : la validation personnalisée n’est pas exécutée.
    • Tester une règle sur plusieurs champs dans clean_<my_field>() au lieu d’utiliser clean() : la logique de validation devient confuse.
