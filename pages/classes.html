    Créer une première vue avec une classe

    En Django, une vue peut être écrite sous la forme d’une fonction, mais aussi sous la forme d’une classe. Cela permet de regrouper le comportement d’une page dans une structure plus organisée. Elle devient particulièrement utile quand plusieurs vues se ressemblent ou quand on veut réutiliser des comportements déjà fournis par Django. 

    from django.http import HttpResponse
from django.views import View


class HomeView(View):
    def get(self, request):
        return HttpResponse("Bonjour depuis une vue de classe !")
    • View est la classe de base des vues Django ;
    • HomeView est la vue créée ;
    • get() correspond à une requête HTTP GET.

    Ici, quand l’utilisateur ouvre la page dans son navigateur, Django exécute la méthode get().

    Relier la vue à urls.py avec as_view()

    Contrairement à une vue fonctionnelle, une vue basée sur une classe ne se relie pas directement dans urls.py. Il faut utiliser la méthode as_view(). 

    from django.urls import path
from .views import HomeView

urlpatterns = [
    path("", HomeView.as_view()),
]

    La méthode as_view() transforme la classe en vue exploitable par Django. Sans elle, Django ne peut pas appeler correctement la vue.

    Afficher un template avec TemplateView

    Si une vue doit seulement afficher un template, Django propose une vue générique déjà prête : TemplateView. 

    from django.views.generic import TemplateView


class HomePageView(TemplateView):
    template_name = "home.html"

    Ici, Django affiche directement le template home.html sans qu’il soit nécessaire d’écrire une méthode get(). Cette solution est pratique pour les pages simples comme :

    • une page d’accueil
    • une page de présentation
    • une page de contact statique

    Afficher une liste d'objets avec ListView

    Pour afficher automatiquement une liste d’objets d’un modèle, Django propose la vue générique ListView. 

    from django.views.generic import ListView
from .models import Student


class StudentListView(ListView):
    model = Student
    template_name = "students.html"
    context_object_name = "students"
    • model indique le modèle utilisé ;
    • template_name indique le template à afficher ;
    • context_object_name définit le nom de la variable envoyée au template.

    Avec cette vue, Django récupère automatiquement tous les objets du modèle Student puis les envoie au template. 

    <ul>
    {% for student in students %}
        <li>{{ student.first_name }} {{ student.last_name }}</li>
    {% endfor %}
</ul>

    Afficher un objet avec DetailView

    La classe DetailView permet d’afficher un seul objet récupéré dans la base de données, alors que ListView en affiche plusieurs. Elle est utilisée pour créer des pages de détail, comme la fiche d'un livre, par exemple.

    On crée d'abord une vue :

    from django.views.generic import DetailView
from .models import Book


class BookDetailView(DetailView):
    model = Book
    template_name = "book_detail.html"
    • model : modèle utilisé pour récupérer l’objet ;
    • template_name : template utilisé pour l’affichage.

    Puis on configure l'URL

    from django.urls import path
from .views import BookDetailView

urlpatterns = [
    path("books/<int:pk>/", BookDetailView.as_view(), name="book_detail"),
]
    • <int:pk> : identifiant de l’objet ;
    • pk = clé primaire (id par défaut).

    Par défaut, l’objet est accessible avec le nom {{ object }}. On peut aussi définir un nom plus explicite : 

    class BookDetailView(DetailView):
    model = Book
    template_name = "book_detail.html"
    context_object_name = "book"

    Dans ce cas, le template utilise {{ book.title }}. Cela rend plus lisible le code Django dans le template. 

    <h1>{{ book.title }}</h1>
<p>Auteur : {{ book.author }}</p>
<ul>
    {% for category in book.categories.all %}
        <li>{{ category.name }}</li>
    {% endfor %}
</ul>

    Erreurs fréquentes

    • Oublier d’hériter de View, TemplateView , ListView ou DetailView : la vue n’a pas le bon comportement.
    • Oublier as_view() dans urls.py : la route ne fonctionne pas.
    • Écrire une méthode get sans paramètre request : erreur lors de l’appel de la vue.
    • Indiquer un template inexistant dans template_name : TemplateDoesNotExist.
    • Utiliser ListView ou DetailView sans préciser le bon modèle : données absentes ou mauvaise vue.
    • Oublier <int:pk> dans l’URL d’une DetailView : Django ne peut pas retrouver l’objet demandé.
    • Ne pas avoir de données dans la base : page vide ou erreur 404.
