    Hériter d'un mixin

    Un mixin est une classe qui ajoute un comportement réutilisable à une autre classe. En Django, les mixins sont souvent utilisés avec les vues basées sur les classes pour éviter de répéter du code. Le code est plus clair et plus facile à réutiliser.

    Un mixin s’utilise en ajoutant une classe supplémentaire dans l’héritage. 

    class MyView(MonMixin, ListView):
    model = Book
    template_name = "books.html"

    Ici, la vue MyView hérite de deux classes : c'est un héritage multiple

    • de MonMixin pour ajouter un comportement spécifique
    • de ListView pour afficher une liste d’objets

    Un mixin ne remplace pas une vue comme ListView ou DetailView : il complète leur comportement.

    Protéger une vue avec LoginRequiredMixin

    Django fournit déjà plusieurs mixins prêts à l’emploi. L’un des plus courants est LoginRequiredMixin. 

    from django.contrib.auth.mixins import LoginRequiredMixin
from django.views.generic import ListView
from .models import Book


class BookListView(LoginRequiredMixin, ListView):
    model = Book
    template_name = "books.html"

    Avec ce mixin, seuls les utilisateurs connectés peuvent accéder à la vue. Si l’utilisateur n’est pas connecté, Django le redirige vers la page de connexion.

    • LoginRequiredMixin ajoute une restriction d’accès
    • ListView gère toujours l’affichage de la liste

    Créer un mixin personnalisé

    Il est aussi possible de créer ses propres mixins pour factoriser du code. Une bonne pratique consiste à créer un fichier mixins.py dans l'application 

    apps/
└── mon_app/
    ├── admin.py
    ├── apps.py
    ├── mixins.py
    ├── models.py
    ├── tests.py
    └── views.py

    Dans ce fichier, on ajoute les mixins : 

    class PageTitleMixin:
    page_title = ""

    def get_context_data(self, **kwargs):
        context = super().get_context_data(**kwargs)
        context["page_title"] = self.page_title
        return context

    Ce mixin ajoute une variable page_title au contexte envoyé au template. On peut ensuite l’utiliser dans plusieurs vues : 

    /span>from django.views.generic import ListView
from .models import Book
from .mixins import PageTitleMixin


class BookListView(PageTitleMixin, ListView):
    model = Book
    template_name = "books.html"
    page_title = "Liste des livres"

    Le template peut alors utiliser : 

    <h1>{{ page_title }}</h1>

    Comprendre l’ordre d’héritage

    Dans une vue utilisant un mixin, l’ordre des classes dans l’héritage est important. En général, le mixin est placé avant la vue principale. Cela permet à Django et à Python d’utiliser correctement les méthodes fournies par le mixin avant celles de la vue générique. 

    class BookListView(LoginRequiredMixin, ListView):
    model = Book

    Quand un mixin redéfinit une méthode comme get_context_data() ou dispatch(), il doit souvent appeler super() pour conserver le comportement normal des autres classes. 

    def get_context_data(self, **kwargs):
    context = super().get_context_data(**kwargs)
    context["page_title"] = self.page_title
    return context

    Erreurs fréquentes

    • Placer le mixin après la vue générique dans l’héritage : le comportement attendu peut ne pas être appliqué correctement.
    • Oublier d’appeler super() dans une méthode comme get_context_data() : une partie du comportement hérité est perdue.
    • Créer un mixin trop gros ou trop spécifique : il devient difficile à réutiliser.
    • Utiliser LoginRequiredMixin sans configurer correctement l’authentification : la redirection vers la connexion ne fonctionne pas comme prévu.
    • Modifier directement le contexte sans vérifier qu’il existe déjà : certaines données peuvent être écrasées.
