    Énoncé

    Vous devez réaliser une application de gestion de projet avec Django.

    1. Objectif général

      • L’application permet de gérer plusieurs projets.
      • Chaque projet contient des tâches.
      • Chaque tâche possède un état d’avancement.
      • L’utilisateur peut consulter les projets, leurs détails et les tâches associées.

    2. Données à gérer

      • Un projet est caractérisé par :
        • un nom
        • une description
        • une date de début
        • une date de fin prévue
        • une image facultative
      • Une tâche est caractérisée par :
        • un titre
        • une description
        • une date limite
        • un niveau de priorité
        • un état à faire / en cours / terminée
        • le projet auquel elle est rattachée.
      • Un membre est caractérisé par :
        • un nom
        • une adresse email
        • un rôle dans le projet
      • Un projet peut avoir plusieurs membres.
      • Une tâche peut être attribuée à un seul membre.
      • Les données sont accessibles depuis l’interface d’administration.

    3. Fonctionnement

      • L’application comporte plusieurs pages :
        • une page d’accueil
        • une page affichant la liste complète des projets
        • une page affichant les détails d’un projet
        • une page affichant la liste complète des tâches
        • une page affichant les détails d’une tâche
        • une page permettant d’ajouter un projet
        • une page permettant d’ajouter une tâche
      • Des liens permettent de naviguer dans l’ensemble du projet :
        • retour à l’accueil
        • accès à la liste des projets
        • accès à la liste des tâches
        • accès au détail d’un projet dès que son nom apparaît
        • accès au détail d’une tâche dès que son titre apparaît
      • Les projets et les tâches doivent être affichés dans un ordre cohérent.
      • L’utilisateur peut créer des projets ou des tâches via des formulaires Django.
      • Les formulaires doivent être validés.
      • Les images envoyées par l’utilisateur doivent être gérées correctement.
      • L’application doit fonctionner avec le serveur de développement Django.

    Conseils de réalisation

    Modèles

    • Créer les modèles dans models.py.
    • Définir Project, Task et Member.
    • Ajouter les relations adaptées entre les tables.
    • Ajouter un ImageField sur le modèle Project.
    • Ajouter les méthodes __str__().

    Base de données et administration

    • Créer les migrations et les appliquer.
    • Enregistrer les modèles dans admin.py.
    • Créer un superutilisateur.
    • Ajouter quelques données de test :
      Projet Tâche Membre État
      Site vitrine Créer la page d’accueil Alice Martin Terminée
      Site vitrine Créer la page contact Lucas Bernard En cours
      Gestion scolaire Créer le modèle Student Emma Dupont Terminée
      Gestion scolaire Créer le formulaire d’ajout Emma Dupont À faire
      Application météo Ajouter l’upload d’images Noah Petit, Lucas Bernard En cours

    Vues

    • Créer des routes et les associer à des vues.
    • Prévoir au minimum :
      • la route / pour la vue "home"
      • la route /projects/ pour la vue "project_list"
      • la route /projects/<int:pk>/ pour la vue "project_detail"
      • la route /tasks/ pour la vue "task_list"
      • la route /tasks/<int:pk>/ pour la vue "task_detail"
      • la route /projects/create/ pour ajouter un projet
      • la route /tasks/create/ pour ajouter une tâche
    • Utiliser :
      • TemplateView pour l’accueil ;
      • ListView pour les listes ;
      • DetailView pour les détails ;
      • CreateView pour les formulaires de création.
    • Ordonner les projets par nom ou par date.
    • Ordonner les tâches par date limite.
    • Envoyer les données avec un context clair dans les vues.

    Formulaires

    • Créer les formulaires dans forms.py.
    • Utiliser ModelForm pour créer un projet et une tâche.
    • Vérifier les données avec is_valid().
    • Utiliser cleaned_data .
    • Ajouter des validations utiles, par exemple :
      • la date de fin d’un projet ne doit pas être antérieure à la date de début
      • la date limite d’une tâche ne doit pas être postérieure à la date de fin du projet
      • le titre d’une tâche ne doit pas être vide
    • Si un projet contient une image, la récupérer dans /media/

    Templates

    • Créer les pages HTML nécessaires.
    • Créer un fichier base.html commun.
    • Afficher clairement :
      • la liste des projets
      • les détails d’un projet
      • la liste des tâches d’un projet
      • les détails d’une tâche
      • les formulaires d’ajout
    • Dans le détail d’un projet, afficher :
      • son nom
      • sa description
      • ses dates
      • son image si elle existe
      • la liste des membres
      • la liste des tâches liées
    • Dans le détail d’une tâche, afficher :
      • son titre
      • sa description
      • son état
      • sa priorité
      • son projet
      • son membre responsable
    • Ajouter une navigation simple et cohérente sur toutes les pages.
