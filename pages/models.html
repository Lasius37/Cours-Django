    Rôle d’un modèle

    Un modèle Django représente une structure de données du projet. Il sert à décrire les informations que l’application doit stocker dans la base de données. Chaque modèle correspond généralement à un type d’objet du projet :

    • un livre dans une bibliothèque
    • un élève dans une application scolaire
    • une tâche dans un gestionnaire de projet

    Un modèle est défini en Python sous la forme d’une classe qui hérite de models.Model.

    Où définir les modèles

    Les modèles sont généralement définis dans le fichier models.py de l’application. 

    apps/
└── mon_app/
    ├── admin.py
    ├── apps.py
    ├── models.py
    ├── tests.py
    └── views.py

    Chaque application peut posséder ses propres modèles. Django utilisera ensuite ces modèles pour créer les tables correspondantes dans la base de données.

    Créer un premier modèle

    Pour créer un modèle, on importe le module models de Django, puis on écrit une classe. 

    from django.db import models


class Student(models.Model):
    first_name = models.CharField(max_length=50)
    last_name = models.CharField(max_length=50)
    age = models.IntegerField()
    email = models.EmailField()
    is_present = models.BooleanField(default=True)

    Ici, le modèle Student représente un élève.

    • first_name stocke le prénom de l'élève
    • last_name stocke son nom
    • age stocke son âge
    • email stocke son email
    • is_present stocke son statut de présence

    Ajouter des champs

    Un champ décrit un type d’information à enregistrer. Django propose de nombreux types de champs. Voici les plus utiles :

    • CharField : texte court
    • TextField : texte long
    • IntegerField : nombre entier
    • BooleanField : vrai / faux
    • DateField : date
    • DateTimeField : date et heure
    • EmailField : adresse email
    • FloatField : nombre décimal

    Certains champs demandent des paramètres, par exemple max_length pour limiter la longueur d’un texte.

    Améliorer l’affichage avec __str__()

    Par défaut, Django affiche les objets d’une manière peu lisible. Il est donc utile d’ajouter une méthode __str__() dans le modèle pour obtenir un affichage plus clair, notamment dans l’administration Django. 

    from django.db import models


class Student(models.Model):
    first_name = models.CharField(max_length=50)
    last_name = models.CharField(max_length=50)
    age = models.IntegerField()
    email = models.EmailField()
    is_present = models.BooleanField(default=True)

    def __str__(self):
        return f"{self.last_name} {self.first_name}"

    Ici, chaque objet Student sera affiché avec son nom complet.

    Générer une migration

    Après avoir créé ou modifié un modèle, il faut préparer les changements à appliquer à la base de données : on doit générer une migration. 

    python manage.py makemigrations

    Cette commande demande à Django d’analyser les changements dans les modèles et de produire un fichier de migration. Django crée alors un dossier migrations dans l’application, avec un fichier du type : 

    apps/
└── mon_app/
    ├── migrations/
    │   ├── __init__.py
    │   └── 0001_initial.py
    ├── models.py
    └── views.py

    Le fichier 0001_initial.py contient les instructions nécessaires pour créer les premières tables du modèle.

    Appliquer les migrations à la base de données

    Créer une migration ne modifie pas encore la base de données : on doit appliquer les migrations avec : 

    python manage.py migrate

    Cette commande exécute les migrations et met à jour la base de données. En pratique :

    • makemigrations prépare les changements
    • migrate les applique réellement

    Erreurs fréquentes

    • Oublier d’hériter de models.Model : Django ne reconnaît pas le modèle.
    • Oublier d’importer from django.db import models : erreur Python.
    • Utiliser un champ sans paramètre obligatoire, comme CharField sans max_length : modèle invalide.
    • Modifier models.py sans relancer les migrations :la base de données n’est pas mise à jour.
    • Lancer makemigrations mais oublier migrate : la migration existe, mais elle n’est pas appliquée.
