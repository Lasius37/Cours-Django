Gérer les fichiers média de l'utilisateur

    Ajouter un fichier avec FileField

    Pour enregistrer un fichier dans un modèle, on peut utiliser FileField. 

    from django.db import models


class Document(models.Model):
    title = models.CharField(max_length=100)
    file = models.FileField(upload_to="documents/")
    • file contient le fichier envoyé
    • upload_to indique le sous-dossier de destination

    Ici, les fichiers seront enregistrés dans le dossier documents/.

    Ajouter une image avec ImageField

    Pour stocker une image, on utilise plutôt ImageField. 

    from django.db import models


class Book(models.Model):
    title = models.CharField(max_length=100)
    cover = models.ImageField(upload_to="covers/")

    ImageField fonctionne comme FileField, mais il est spécialisé pour les images. Il nécessite généralement l’installation de la bibliothèque Pillow.

    Configurer MEDIA_URL et MEDIA_ROOT

    Pour que Django sache où enregistrer et servir les fichiers media, il faut ajouter deux variables dans settings.py. 

    MEDIA_URL = "/media/"
MEDIA_ROOT = BASE_DIR / "media"
    • MEDIA_URL définit l’URL de base des fichiers media
    • MEDIA_ROOT définit le dossier réel de stockage

    Ici, les fichiers seront enregistrés dans un dossier media à la racine du projet.

    Servir les fichiers dans urls.py

    En développement, il faut aussi configurer urls.py pour que Django puisse afficher les fichiers envoyés. 

    from django.conf import settings
from django.conf.urls.static import static
from django.urls import path

urlpatterns = [
    # les routes du projet
]

if settings.DEBUG:
    urlpatterns += static(settings.MEDIA_URL, document_root=settings.MEDIA_ROOT)

    Cette configuration permet d’accéder aux fichiers media pendant le développement. En production, la gestion des fichiers media se fait généralement autrement.

    Envoyer un fichier avec un formulaire

    Pour envoyer un fichier, le formulaire HTML doit utiliser l’attribut enctype="multipart/form-data". 

    <form method="post" enctype="multipart/form-data">
    {% csrf_token %}
    {{ form.as_p }}
    <button type="submit">Envoyer</button>
</form>

    Dans la vue, il faut transmettre à la fois request.POST et request.FILES. 

    from django.shortcuts import redirect, render
from .forms import DocumentForm


def upload_document(request):
    if request.method == "POST":
        form = DocumentForm(request.POST, request.FILES)
        if form.is_valid():
            form.save()
            return redirect("home")
    else:
        form = DocumentForm()

    context = {"form": form}

    return render(request, "upload.html", context)

    Sans request.FILES, Django ne récupère pas le fichier envoyé.

    Afficher le fichier dans un template

    Une fois le fichier enregistré, on peut accéder à son URL dans le template. 

    <a href="{{ document.file.url }}">Télécharger le document</a>

    Pour une image, on peut l’afficher directement : 

    <img src="{{ book.cover.url }}" alt="{{ book.title }}">

    L’attribut .url donne l’adresse du fichier enregistré.

    Erreurs fréquentes

    • Confondre static et media : les fichiers utilisateur sont mal gérés.
    • Oublier MEDIA_URL ou MEDIA_ROOT dans settings.py : Django ne sait pas où stocker ou servir les fichiers.
    • Oublier la configuration static(settings.MEDIA_URL, document_root=settings.MEDIA_ROOT) dans urls.py en développement : les fichiers ne s’affichent pas.
    • Oublier enctype="multipart/form-data" dans la balise <form> : le fichier n’est pas envoyé.
    • Oublier request.FILES dans la vue : le formulaire reçoit les champs texte mais pas le fichier.
    • Utiliser ImageField sans installer Pillow : erreur lors de la gestion des images.
    • Essayer d’utiliser {{ document.file.url }} alors qu’aucun fichier n’a été envoyé : erreur d’affichage ou valeur absente.
